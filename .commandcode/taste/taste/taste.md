# Taste
- Prefers comprehensive, codebase-wide sweeps over narrowly scoped fixes: when asking to "do the TODO", expects the agent to check all source files and proactively find and complete empty/stub pages and other unfinished implementations, not just the explicitly named items. Confidence: 0.6
- Reports bugs tersely — either pasting raw server/dev-server logs (e.g., a 307 redirect-loop log dump) or a bare one-liner like "scrollbar-none is not working..." — with minimal context, expecting the agent to investigate, reproduce, and fix autonomously rather than asking for more details. Confidence: 0.6
- Prefers a managed, serverless PostgreSQL (Neon) for the database over local file-based SQLite — explicitly asked to drop SQLite and move the connection string (already placed in `.env.local`) to a hosted Postgres. Confidence: 0.7
- When diagnosing bugs, verifies the actual runtime behavior against a live dev server with `curl` (checking HTTP status codes, redirect URLs, and rendered content) rather than relying on typecheck/build alone. Confidence: 0.6
- Wants all user-facing errors and warnings to be human-friendly: plain-English, conversational, and actionable messages rather than raw error codes, stack traces, or technical jargon (e.g., mapping driver errors like ECONNREFUSED to "We couldn't reach your database..."). Confidence: 0.9
- Prefers user-facing errors to be formatted as helpful step-by-step guidance ("Here's how to fix it" numbered list) with a prominent humanized message and a "try again" action, instead of just displaying raw error text. Confidence: 0.6
- Values security-conscious messaging: keeps failure messages generic (e.g., a single login error that doesn't reveal whether an email exists) to avoid account enumeration. Confidence: 0.6
- Expects UI work to reuse the existing shared component library (`components/ui`, e.g. shadcn-style components like Button, Card, Input, Toaster) rather than hand-rolling markup; asks pointedly when agent changes appear to bypass it. Confidence: 0.6
- Wants password fields to include a show/hide toggle (eye open/close icon) as a standard form affordance, applied to every password input (setup, login, confirm-password), not just one. Confidence: 0.8
- Cares about visual detail in forms: a full-width submit button sitting flush below input fields looks "attached to the input" and should be visually separated (e.g., top border + padding + margin on the card footer) so the action reads as its own distinct section. Confidence: 0.6
